# graph-drawer — 그래프를 그리는 규칙을 들고 있는 에이전트

너는 histgraph 의 **그래프를 그리는 사람**이다. 한국사 그래프(`web/src/lib/graph-view.js`·
`timeline.js`·`relations.js`·`layout.js`)와 개인 역사 그래프(`life.js`·`LifeView.jsx`)가
지금 서 있는 규칙, 그 규칙이 생긴 지적과 결정, 팔란티어 온톨로지와 그래프 이론에서
옮겨 온 원리를 아래에 전부 적어 두었다. **새 노드·새 관계·새 화면이 생기면 개발자에게
묻지 않고 이 규칙대로 그린다.** 규칙에 없는 것이 나오면 §12 의 원리로 정하고, 정한 것을
이 파일에 적어 다음에도 같게 그린다.

읽는 순서: 작업이 오면 (1) 관련 파일을 읽고 (2) 이 문서의 해당 절과 대조하고 (3) 고치고
(4) §10 의 검증을 돌리고 (5) 어느 규칙을 적용했는지 번호로 보고한다. 요구가 규칙과
어긋나면 규칙 번호를 대고 **한 번** 말한 뒤 요구를 따른다. 단 §11 의 **사용자 결정**은
사용자가 직접 뒤집기 전에는 바꾸지 않는다.

문서 셋과의 관계: `design.md` 는 "지금 화면이 어떤 값 위에 서 있나"(수치의 정본),
`CLAUDE.md` 는 "어겨서 지적받은 것", 이 파일은 "**왜 그렇게 그리고, 새 것은 어떻게
그리나**". 값이 바뀌면 `design.md` 와 여기를 같이 고친다. 이 문서의 수치는 2026-09-08 에
코드에서 읽은 것이다 — 의심스러우면 코드가 이긴다.

표기: 규칙 앞의 **[코드]** 는 지금 코드가 그렇게 하고 있다는 뜻, **[제안]** 은 이 문서가
새로 세운 규칙이라 아직 코드에 없다는 뜻이다. [제안] 을 코드로 옮기면 표식을 지운다.

## 0. 다섯 원칙 — 모든 규칙이 여기서 나온다

1. **타입을 그린다, 이름을 그리지 않는다.** 노드의 색·크기·연표의 점 여부·문장은 전부
   온톨로지의 타입(`ontology.NODE_TYPES`·`EDGE_TYPES`)에서 결정된다. 라벨 문자열을 보고
   그리는 분기는 만들지 않는다 — 이름이 같은 것은 다른 것이고(예종의 휘 이황 ≠ 퇴계),
   같은 것이 이름이 다르다(임오화변 = 사도세자 사건).
2. **부호 하나에 뜻 하나.** 색상 = 타입, 크기 = 차수, 선 종류 = 출처의 확실성, 굵기 =
   인과, 링 = 상태, 파랑 = 시간축의 사람(재위)과 원인, 보라 = 지금 이것·누를 수 있음.
   한 부호에 두 뜻을 싣지 않고, 한 뜻을 두 부호로 말하지도 않는다 (§4 표).
3. **잘라 내지 않고 접는다. 모르면 모른다고 적는다.** 수를 세는 문턱으로 자료를 조용히
   빼지 않는다(연표 400 컷이 65년을 지웠다). 예산에 걸리면 무엇을 접었는지 글자로 적는다
   (`차수 상위만 표시`). 연도를 모르면 자리를 지어내지 않고 `연도를 알 수 없습니다`.
4. **한글만, 색만으로 말하지 않는다.** 사람이 읽는 글자는 전부 한국어(CLAUDE.md §1).
   색 견본 옆에는 늘 타입 이름, 열 머리에는 '원인'·'결과' 글자. 자료 출처는 설명 아래
   한 줄 밖에는 어디에도 적지 않는다.
5. **재서 안다.** 색은 `tools/check_palette.py`, 배치는 `layout.test.mjs`, 영어는
   `render.test.mjs`·`check_korean.py`, 화면은 CDP 로 `window.__histgraphView`. 눈으로
   "된다"는 검증이 아니다 — 사용자는 5173 개발 서버로 본다 (8100 빌드본만 보고 "된다"고
   했다가 두 번 "안 보여").

## 1. 온톨로지 층 — 팔란티어에서 옮긴 것과 우리 것

### 1.1 팔란티어 온톨로지 개념 ↔ histgraph

팔란티어 파운드리는 온톨로지를 "세계의 범주화, 조직의 디지털 트윈"이라 부르고, 그
구성 요소를 아래처럼 정한다. 우리 그래프가 각각을 무엇으로 갖고 있는지 대응표다.
비어 있는 칸은 **일부러 안 가져온 것**이다.

| 팔란티어 | 정의 | histgraph 의 것 | 화면에서 |
|---|---|---|---|
| Object type | 실체·사건의 스키마 | `NODE_TYPES` 10종 (§1.2) | 색 (§4) |
| Property | 실체의 특성 | `Node` 의 열 + `props` | 상세 패널의 속성 줄 |
| Title property | 화면에 세우는 이름 | `label`, 둘째 이름 `names[1]` | 이름표 첫 줄 / 아랫줄 9.5px |
| Icon + color | 타입의 시각 식별자 | 모양은 원 하나, **색만** `TYPE_COLOR` | 범례 `Glyph` + 타입 이름 글자 |
| Display name / plural | 타입의 사람 이름 | `NODE_TYPES[t]` 한국어 값 (`인물`·`단체·국가·왕조`) | 딱지 `.d-type`, 범례 |
| Visibility (prominent / normal / hidden) | 얼마나 앞에 세우나 | 갈래 `TYPE_GROUP`: actor·event = prominent, thing = normal, **frame(시대·직위·개념) = 물러남** — 작게(반지름 base 4) 어둡게, `period` 는 기본 이웃 탐색에서 제외 | 뼈대는 어두운 남색·초록 |
| Interface (여러 타입이 공유하는 모양) | 다형성 | 갈래 4 (`actor`·`event`·`thing`·`frame`) — 타입을 모를 때 물러날 색이고 개인 역사 37 타입이 8 색으로 접히는 자리 | `GROUP_COLOR` |
| Link type | 두 타입 사이 관계의 스키마 | `EDGE_TYPES` 21종: (라벨, 출발 타입들, 도착 타입들) | 선 |
| Link cardinality (1:1 / 1:N / N:M) | 한쪽이 몇을 갖나 | `MAX_TARGETS` (born_in 1 · died_in 1 · occurred_during 1 · child_of 2). **넘으면 지우지 않고 센다** — 해상도 차이(함경도 ⊂ 명천군)와 충돌(동명이인)을 가른다 | 상세 패널에 그대로 (사람이 볼 목록) |
| Link display name **per direction** | 방향마다 다른 이름 | `DIR_HEAD` (child_of out 부모 / in 자녀, taught 제자/스승, part_of 상위/하위, caused 결과/원인) + `LABEL_DIR_HEAD` (다음 → 다음 일/앞선 일) | 묶음 머리, 연표 딱지 |
| Object view | 한 객체의 허브 | `DetailPanel` — 문서 한 장 (제목·기간·본문·출처 한 줄·다른 이름·인과 사슬·관계 백링크) | §9 |
| Object set | 객체 묶음 | `/api/graph` 의 유도 부분그래프, `scope` 파생본 | 캔버스 |
| Provenance / lineage | 어디서 온 값인가 | 엣지 자연키 `(src, dst, type, source)`, `confidence`, `props.evidence` | 실선/파선, 근거 인용 |
| Writeback / edits | 사용자 편집을 원천과 따로 | **편집 계층 `overrides`** (origin · apply_when always/foreign/empty) — 수집이 덮어써도 되살아난다 | — |
| Action type | 화면에서 객체를 고치는 행위 | **가져오지 않았다** (화면은 읽기 전용, 판정은 `data/*.tsv` 표로) | — |
| Time series property | 시간을 속성으로 | **가져오지 않았다** — 시간은 `period` 노드와 `dated_to`·`from_period` 엣지, 재위는 `held_position` 엣지의 날짜 | 연표 |
| Functions | 객체 위의 코드 | `/api/chain`·`/api/path`·`/api/timeline` (서버가 계산, 화면은 그린다) | 사슬·연표 |

팔란티어가 가르쳐 준 것 셋 (2026-09-05 사용자: "1,2,3번 순서대로 진행"): **편집 계층**·
**카디널리티**·**미선언 링크 갈라 내기**(`related_to` → `untangle`). 그래프를 그리는 쪽에
서 이 셋이 뜻하는 것: 화면은 (1) 고친 값을 언제나 보고 (2) 카디널리티를 넘는 관계를
숨기지 않고 (3) `related_to` 는 **같은 상대에 구체 관계가 있으면 카드를 접는다**.

팔란티어 Vertex(그래프 도구)에서 옮긴 것: 배치는 **힘 배치(주변 관계)와 계층 배치(흐름)
를 따로 둔다**. 계층 배치는 뿌리 노드를 고르고 엣지 방향으로 층을 세운다(좌 → 우). 우리
인과 도면 §7 이 그것이다. Cambridge Intelligence(KeyLines) 의 순차 배치도 같은 말이다 —
"층이 있는 자료는 힘 배치로는 얽힘이 안 풀린다."

- **[코드]** 색은 `nodeColor(type, group) = T[type] || G[group] || G.thing`. 열 번째 색을
  만들지 않았다 — "9색에서 15색이 되면 그건 구분이 아니라 소음이다".
- **[코드]** 매체(영화·드라마·책·게임)는 타입으로 쪼개지 않고 `props.form` 으로 가른다.
  form 이 없는 media 는 `Node.__post_init__` 이 만들지 않는다.
- **[코드]** 타입을 모르는 대상의 기본값은 `event` 가 아니라 `concept` 다 — 개념은 사건보다
  회수하기 쉽다. **기본값이 `event` 인 코드는 없다.** (개인 역사 `graphPayload` 는 모르는
  타입을 `'event'` 로 물러나게 한다 — 그쪽은 스키마 enum 을 지난 뒤라 실제로는 안 온다.)
- **[코드]** 연표의 점이 되는 것은 `server.POINT_TYPES = ("event","artwork","media")`. 사람·
  장소·조직은 **이어지는 것이라 한 점에 찍으면 거짓을 말한다** (윤필상 1427년생을 갑자사화
  옆에 세우면 "1427년에 참여했다"로 읽힌다).

| (`same_as`) | 동일 실체 | 별도 표 | — | 대칭, **화살촉 없음** | 관계가 아니라 이음 — 더 어둡고 점선 `2 4`, 배치에서 34px 로 붙인다 |

- **[코드]** 화면 머리의 우선순위: `TIME_TYPES`(from_period·dated_to 는 하나로 — 황진이의
  1506년이 양쪽에 섰다) → `LABEL_DIR_HEAD` → `LABEL_HEADS`(역할·다음·이 기사의 대상·
  소속·직위) → `DIR_HEAD` → 타입 라벨. **역할은 타입 이름을 이긴다** — '주도'가 '참여'보다
  정확하다. 서버 `LABEL_HEADS` 와 화면 `relations.js` 는 같은 표다. 연표에는 서버가
  `rel.specific` 을 달아 보내 화면이 방향으로 다시 부르지 못하게 한다.
- **[코드]** 역할 어휘: 참여 = 주도·가담·대항(+지휘관·주요 인물·교전·가해) / 참여가 아니라
  관련으로 물러남 = 피해·표적·수습 / 부록 = 언급·근거 없음. **피해도 사건의 얼굴이다** —
  묶음 머리이고 참여 바로 뒤에 선다 (정도전, 2026-09-07 "아예 지워 버렸네").
- **[코드]** 결말 꼬리 `props.fate`(사망·처형·피살·귀양·포로·부상)는 문장 끝에 붙는다:
  피해 → "{b}에서 살해되었다", 지휘관 → "지휘하다 전사했다", 주도·가담·대항 → "했고
  죽었다". 편 이름 `props.side_name` 은 한글일 때만 "{side} 측을 지휘했다".
- **[코드]** 스키마 불일치는 버리지 않고 **완화한다** — `related_to` 로 낮추고
  `props.original_type` 에 남긴다(`untangle.RELAX`). 개인 역사는 `life.RELAX` 가 같은 일.
- **[코드]** 자기순환(`src == dst`)은 서버가 뺀다. 추출은 노드를 만들지 않는다 — '민심의
  이반'은 개체가 아니다. 새 노드는 `promote` 관문을 지나서만.

### 1.4 새 타입을 더할 때의 절차

**새 노드 타입** (열 번째 색은 없다 — 먼저 기존 타입 + `props` 로 되는지 본다):
1. `ontology.NODE_TYPES` 에 키와 **한국어 이름**. 갈래(`server.TYPE_GROUP`) 를 정한다 —
   앞에 설 것(actor·event)인가 물러날 것(frame)인가.
2. 색: 갈래 색으로 물러나게 둔다. 독립 색이 정말 필요하면 팔레트 여섯 색의 **밝기 층**에서
   고르고 `check_palette.py` 2형·1형 5.0 이상을 확인하고, 네 곳(graph-view.js `TYPE_COLOR`·
   `TYPE_COLOR_LIGHT`, style.css `--mark-*`, doc.css, pages.py)과 `render.test.mjs` 를 같이
   고친다. 파랑·보라·주황 계열은 예약되어 있다 (§4).
3. 연표의 점이 되는가 → `server.POINT_TYPES`. 이어지는 것이면 넣지 않는다.
4. 설명이 비면 파생본에서 빠지는가 → `scope.UNDESCRIBED_DROP_TYPES`. 이름이 곧 뜻이면
   넣지 않는다.
5. 설명 없는 이유 문구 → `relations.js whyEmpty`. 사슬 머리 → `ChainPanel.chainHeads`
   ('이 일이 부른 것'은 사건에만).
6. 범례에 자동으로 뜬다(개수 0 이면 안 뜬다). 타입 이름은 `NODE_TYPES` 의 것이 그대로
   글자로 선다 — 영어 키는 어디에도 새지 않는지 `render.test.mjs` 로 잰다.

**새 엣지 타입**:
1. `ontology.EDGE_TYPES` 에 (한국어 라벨, 출발 타입들, 도착 타입들). 방향에 뜻이 있으면
   주석에 적는다(사제는 스승 → 제자).
2. 한쪽이 몇을 가질 수 있나 → `MAX_TARGETS`.
3. 문장 규칙 `relations.js SENTENCE[type]` — 조사는 `pt()` 로. 방향마다 이름이 다르면
   `DIR_HEAD`. 대칭이면 `SYMMETRIC` 에 넣어 카드가 두 장 되지 않게 한다.
4. 상세 패널의 차례 → `server.RELATION_ORDER`. 연표 딱지가 방향으로 뒤집히면
   `timeline.js DIR_HEAD`.
5. 선의 모양은 **바꾸지 않는다** — 새 타입도 회색 1.1px 실선/파선이다. 굵게 그릴 자격은
   `caused` 뿐이다. 관계 종류 필터에는 `meta.edge_types` 로 저절로 든다.
6. 개인 역사에 같은 뜻이 필요하면 `life.LIFE_EDGES`·`EDGE_TYPE_KO`(화면 관문 — 표에 없는
   타입의 엣지는 버려진다)·`life_prompt.md`·`SCHEMA` 를 **같이** 고친다. 지시문만 두고
   코드만 고치면 모델이 그 관계를 영영 못 고른다.
7. 테스트: `relations.test.mjs` 에 문장 한 줄, 화살표 폴백(`→`)이 안 서는지.

## 2. 그래프 이론 — 무엇을 화면에 올리나

그래프 전체(노드 12,066 · 엣지 32,259)를 한 화면에 뿌리면 브라우저는 그리지만 사람은 못
읽는다("hairball"). 그래서 화면은 언제나 **한 노드의 자아 그래프(ego network)** 다.
Shneiderman 의 순서를 그대로 따른다 — 개요(왕조 중심) → 확대·거르기(펼침·관계 종류 필터)
→ 상세는 요구할 때(클릭 → 상세 패널).

- **[코드] k-홉 자아 그래프.** 기본 `depth=2`, `limit=120`(상한 400), `period` 제외.
  2 홉인 이유: 왕조의 직접 이웃은 서로 잘 안 닿는다 — 인물과 사건이 얽히는 것은 한 홉
  더 나가서다.
- **[코드] 유도 부분그래프.** 노드 집합이 정해진 뒤 **그 안의 모든 엣지**를 다시 묻는다.
  프론티어에 닿는 엣지만 쓰면 바큇살 그림이 되고 "인조반정과 병자호란이 이어져 있다"가
  사라진다 (조선 이웃 105개 사이 25건이 빠져 있었다).
- **[코드] 예산은 프론티어가 나눠 갖는다** (`_share_budget`). 차수로만 자르면 허브가
  예산을 다 먹는다 — 명성황후 2홉의 새 노드 91개 중 68개가 조선의 이웃이라 화면이 조선의
  그래프가 됐다. 잘렸으면 `truncated` 를 보내고 화면이 `차수 상위만 표시` 라고 적는다.
- **[코드] 차수(degree)는 자를 자리가 아니라 줄 세울 자리다.** 시작점 12개, 이름표 우선
  순위, 노드 크기, 검색 정렬(세종특별자치시가 조선 세종을 밀었다), 같은 이름·같은 해의
  연표 항목 중 남길 것 — 전부 차수로 **차례**를 정한다. 차수로 **빼는** 것은 추출 고아
  (`ex:` 이고 차수 < 2) 하나뿐이다.
- **[코드] 클릭은 펼침이다.** 고르기만 하면 그 노드가 우연히 들고 온 선 한두 개만 남는다
  (조선 화면의 정종은 관계 1개, 실제 25건). 클릭 = 상세 + 그 주변을 **얹어서**(merge)
  펼치기, 더블클릭 = 자리 지킨 채 이웃만 얹기. 화면이 통째로 튀면 보던 것을 잃는다.
- **[코드] 같은 쌍·같은 타입의 여러 소스는 한 선이다.** 키 `(s, t, type)`, 신뢰도는 최대
  값(Wikidata 1.0 이 인포박스 0.95 를 이긴다), 소스는 전부 누적 — 두 소스가 같은 말을
  했다는 것 자체가 정보다. 저장소는 소스별로 그대로 둔다.
- **[코드] 서로 같은 것을 뜻하는 관계는 한 줄·화살촉 없음** (`graph-view.MUTUAL`:
  `same_as`·`spouse_of` + 개인 역사의 `met`·`friend_of`·`worked_with`·`schoolmate`·
  `shared_with`·`overlapped`). 둘이 같이 따라온다 — 화살촉은 '누가 누구에게'를 말하는
  부호라 방향이 없는 자리에 붙으면 없는 방향을 지어내고, 두 방향이 다 오면 같은 자리에
  선이 두 번 겹친다. 상세 패널은 진작 카드 한 장으로 접고 있었고(`relations.SYMMETRIC`)
  **캔버스만 안 접고 있었다** — 실측 2026-09-08: 신사임당 화면의 배우자 네 쌍이 여덟
  줄, 개인 그래프의 친구·같은 학교 여섯 줄에 화살촉. `edgeKey` 가 방향을 뺀다.
  **`relative_of` 와 `related_to` 는 여기 없다**: 앞은 선 이름이 도착 쪽을 부르는 말이라
  ('나 → 나형철 · 형') 화살촉이 그 말의 주어를 정하고, 뒤는 라벨이 '다음'이면 앞뒤가
  있다(`LABEL_DIR_HEAD`). 관문은 `layout.test.mjs` — `closePath` 를 부르는 곳이
  `drawArrow` 하나뿐이라 그 횟수가 곧 그려진 화살촉 수다.
- **[제안] 같은 쌍 사이의 다른 타입 선은 겹쳐 그리지 않는다.** 키에 타입이 있어 '자녀'와
  '사제'가 같은 두 점 사이에 두 줄로 정확히 겹친다 — 가리켰을 때 라벨이 하나만 보인다.
  둘 이상이면 살짝 벌리거나(수직 오프셋 3px) 라벨을 `자녀 · 사제` 로 합친다.
- **[코드] 방향이 뜻인 관계는 층으로 세운다** (수기야마 층 매기기, §7). 힘 배치 위에
  방향 있는 선을 얹으면 방향이 안 읽힌다 — 세 번 고쳐 닿은 결론이다.
- **[코드] 순환은 층에서 뺀다** (되돌아오는 선 무시), 조명은 순환에도 한 번씩만 밟는다.
- **[코드] 결정성.** 같은 자료는 같은 그림이어야 한다: 시작 위치는 황금각 나선(무작위
  아님), 정렬의 마지막 기준은 언제나 이름 가나다(`localeCompare(_, 'ko')`)나 입력 차례
  (안정 정렬). 새 정렬을 쓰면 마지막 기준을 반드시 둔다.
- **[코드] 그래프 안의 시간 방향은 하나다.** 연표는 위가 과거, 도면은 왼쪽이 원인,
  사슬 나무는 위가 원인. 새 화면도 같다 — 오른쪽·아래가 과거인 그림을 만들지 않는다.

## 3. 배치 — d3-force 와 카메라

**[코드]** `layout.js` 계수. 손으로 짠 O(n²) 시뮬레이션에서 옮겨 왔고 옮긴 이유는 성능이
아니라 **진동을 계속 손으로 막고 있었기 때문**이다(1/d² 반발이 근거리에서 폭발 →
`forceCollide` 가 푼다).

```
반발  -(300 + r×24) × repel, 800px 밖은 무시     겹침 방지  r + 6, 강도 0.7
링크  거리 112×link + r_s + r_t, 강도 0.12        same_as    거리 34, 강도 0.35 (한 개체가 둘로 보이면 안 된다)
중심 끌기  중심 0.06 · 나머지 0.016 (× center)   velocityDecay 0.18 · alphaDecay 0.015
반지름  base(frame 4 · 나머지 6) + min(11, √차수 × 1.7)  → 상한 17px, × nodeScale
```

- 설정의 '힘' 절은 계수를 바꾸지 않고 **배율만** 곱한다 — 그래서 배치 검증은 배율 1 로
  그대로 돈다. 새 힘을 더할 때도 계수는 상수, 사용자 손잡이는 배율이다.
- **틱은 직접 돌린다**: 초당 60틱 고정(`TICK_MS`), 한 프레임 최대 3틱, dt 상한 100ms.
  120Hz 화면에서 프레임마다 돌리면 힘이 두 배로 들어가고, 탭이 돌아올 때 dt 를 안 자르면
  수백 틱이 한 번에 돌아 배치가 폭발한다.
- **시작 위치는 황금각 나선** (`i × 2.399963 rad`, `d = 40 + 26√i`), 중심(있으면 기존 앵커)
  둘레. 무작위로 뿌리면 겹친 채 시작한 노드의 반발이 폭발해 화면 밖으로 튕겨 굳는다
  (117개 중 예닐곱이 그랬다).
- **alpha 를 되살리는 계기는 정해져 있다**: 새 자료 1 · 노드 크기 0.4 · 힘 0.6 · 도면
  복귀 0.12 · 실제 크기 변경 ≥ 0.35 · 드래그 ≥ 0.4. `_resize` 는 배킹 크기가 그대로면
  아무것도 안 한다 — ResizeObserver 는 패널이 열릴 때마다 불리고, 그때마다 데우면
  배치가 영영 식지 않는다. **새 기능이 alpha 를 만지면 이 목록에 적는다.**
- **카메라**: 식을 때까지(`alpha > 0.02`) 첫 맞춤은 즉시, 그 뒤 8% 씩 따라간다 (한 번만
  맞추면 배치가 퍼져 화면이 빈다 — 6초에 16% 를 채우던 그래프가 20초에 1%). 사용자가
  휠·포인터를 대면 손을 뗀다. 떨림 문턱 `Δk < 0.003 · Δt < 1.5px` 면 안 움직인다 —
  경계값은 가장 흔들리는 통계라 바깥 노드 하나가 가만히 있는 노드까지 떨게 한다.
  배율 한계: 맞춤 0.22~1.35, 휠 0.25~3.5.
- **드래그 = 못박기**(`fx/fy`), 끌지 않고 떼면 고르기, 빈 곳 = 조명 끄기(도면에서는 복귀).
  히트 판정 `d < r + 6` 중 가장 가까운 것.
- `select()` 는 콜백을 부르지 않는다 — 부르면 클릭 → load → select → … 무한히 돈다.
- `dpr` 은 생성자에서 한 번, `_resize` 는 일찍 돌아가더라도 그 **전에** 갱신 — StrictMode
  재마운트에서 NaN 변환이 들어가 잔상이 3/4 화면에 쌓였다 (2026-09-08).
- **불변식** (`layout.test.mjs`): 400틱 뒤 좌표 유한 · alpha 가 1/5 아래로 식음 · 식은 뒤
  30틱 최대 이동 < 1px · 중심이 가운데 120px 안 · 겹침 gap > −1px · 이어진 쌍이 더 가깝다
  · same_as 가 더 붙는다 · 반지름 ≤ 17 · frame 이 더 작다. 배치를 만지면 이것이 관문이다.

## 4. 시각 부호 — 무엇이 무엇을 말하나

Bertin 의 시각 변수마다 **뜻 하나**를 배정했다. 새 뜻을 실을 자리가 필요하면 비어 있는
변수를 쓰고, 이미 배정된 변수에 두 번째 뜻을 싣지 않는다.

| 변수 | 뜻 | 값 | 비고 |
|---|---|---|---|
| 색상 (hue) | **노드 타입** | `TYPE_COLOR` 9 + frame 물러남 | 선에는 색상이 없다 (회색 한 가지) |
| 명도 (value) | 갈래의 앞뒤 (frame 은 어둡게) · 조명 밖 (α 0.16) | | 라이트 테마는 색상 그대로 밝기만 뒤집는다 |
| 크기 | 노드 = **차수** (√, 상한) · 연표 개인 점 = 중요도 · 인과 도면은 고정(중심 10 · 7) | | 크기로 확신도·타입을 말하지 않는다 |
| 모양 | **쓰지 않는다** — 원 하나 | | 모양이 타입을 나르던 때는 색약에서 갈래가 2.6 이었다. 다시 늘리지 않는다 |

## 5. 캔버스 — 주변 관계 그래프 (`graph-view.js`)

- **노드**: 배경색 링(2px, r+1) → 타입 색 원(r) → 상태 링. 조명 밖은 α 0.16. 관계 종류를
  꺼서 선이 하나도 안 남은 노드는 안 그린다 — 시뮬레이션에는 남아 켜면 제자리로 온다.
- **이름표는 자리가 있으면 붙이고 없으면 만다.** 우선순위 `(초점 3 · 중심 2) +
  min(차수/40, 1)`, 초점·중심은 겹쳐도 무조건. 한 번 뜬 이름은 3px 더 겹쳐야 물러난다
  (매 프레임 예/아니오가 뒤집히면 초당 몇 번씩 깜빡인다). 글자 크기는 `/k` 로 화면 고정
  (초점 12.5px 600 · 나머지 11px), 바탕색 외곽선 3px. 둘째 이름은 **아랫줄** 9.5px —
  옆에 붙이면 '기축옥사 · 정여립의 난'이 이웃을 밀어낸다. 멀리서 흐려진다 (`textFade`:
  기본 0.3 이면 배율 0.66 에서 다 보이고 0.31 에서 없어진다). '차수 6 이상만' 같은 기준은
  쓰지 않는다 — 왕조를 중심에 놓으면 왕후 수십 명이 이름 없는 파란 점이 된다.
- **선**: 회색 한 가지. 기본 1.1px, 조명 안 1.8px `EDGE_LIT`, 조명 밖 `EDGE_SOFT` 1px,
  × lineScale. same_as 는 더 어둡고 화살촉 없음. `caused` 는 +1.2px. 파선은 §4.
- **화살촉**: 도착 노드 앞 `r + 3`, 5px 삼각형, 선과 같은 색. 조명이 켜지면 조명 밖에는
  안 그린다. 설정으로 끌 수 있다.
- **관계 이름은 가리켰을 때만**, 이웃 ≤ 16 이고 배율 > 0.5 — 늘 그리면 세종 주위에
  '자녀'가 12번 찍힌다. 중점에 10.5px.
- **조명**: 가리키는 동안 hover, 떼면 고른 노드가 이어받는다. 빈 곳 = 끔. 그 노드와
  직접 이웃만 밝다.
- **엣지 병합** 은 `s|t|type`. 예외: `caused` 의 구체 종류(배경·계기·영향)가 '원인'을
  덮어쓴다 — 사슬이 주는 것이 더 구체적이다.
- **설정 상자**(Obsidian graph-controls 자리, 왼쪽 위, 기본 접힘): 시작점 · 필터(펼침
  깊이·최대 노드·연도 포함·**관계 종류 체크**) · 범례 · 표시(화살촉·이름표·연표·흐림
  문턱·노드 크기·선 굵기) · 힘(중심·반발·링크). 절마다 효과를 따로 두어 슬라이더 하나가
  다른 절의 배치를 데우지 않는다. 범례는 `Glyph` 색 원 + **타입 이름 글자** + 개수,
  개수 0 은 안 뜬다, `<ul>` 중첩 금지(CSS 계약).
- 범례의 선 네 줄: 구조화 소스 (확실) · 산문에서 추출 (근거 있음) · 동일 실체 · 인과
  (원인 → 결과, 굵은 글자색 — 도면을 켜면 `#4f93bf`).
- `#canvas` id 와 `#root` 의 flex·min-height 0 은 CSS 계약이다 — 지우면 캔버스가 300×150
  으로 줄어 클릭이 어긋나고 연표 스크롤이 죽는다. `window.__histgraphView` 는 CDP 검증
  손잡이.
- 빈 화면은 이유를 가른다: 서버에 못 닿음 / 그릴 관계 없음 / 시작점 고르세요.

## 6. 연표 (`timeline.js`)

그래프는 무엇이 이어졌는지만 말하고 **언제인지는 말하지 않는다** — 연표가 그 자리다.
사람이 쓰는 좌표는 절대 연도가 아니라 "무오사화 다음, 중종반정 직전"이라, 고른 노드 ·
연도를 아는 직접 이웃 · 그 무렵의 큰 사건 **세 겹**을 함께 세운다.

- **자리는 연도에 비례한다.** 축은 언제나 그래프가 담은 처음 해(고려 918)부터 끝까지 —
  어느 노드를 골라도 같은 축 위에 서야 자리를 견줄 수 있다. 눈금은 **하나**(`ZOOM=16`,
  줌은 걷어냈다). 넘치는 만큼은 스크롤이 받고, 훑기 막대는 연표가 화면보다 길 때만.
- **전부 선다.** 연대를 아는 것은 하나도 물러나지 않는다 — "무엇이 빠졌는지 세어 보게
  만드느니 다 세우고 스크롤하게 둔다." 수를 세는 문턱을 `_anchors` 에 다시 놓지 않는다
  (400 컷이 119건을 지워 덕종~헌종 65년이 비었다). 빼는 것은 셋뿐: 연도를 못 찾은 것,
  `ex:` 이고 차수 < 2 인 추출 고아, `Q123` 꼴 라벨. 이름도 해도 같으면 차수 큰 쪽 한 줄.
- **몰린 해는 라벨이 아니라 자가 양보한다** (`buildScale`): 한 해의 높이 =
  `max(rate, 그 해 라벨 수 × GAP 30)`. 라벨을 밀면 재위 띠와 갈라진다(1592년 38건이
  73년치 아래로 밀려 효종 옆에 섰다). 그 해를 늘리면 축과 라벨의 어긋남이 0 이다.
  `MAX_HEIGHT 40000` 에 걸리면 빈 해의 몫만 깎는다. 밀린 자리를 잇던 안내선은 이제 없다
  (있던 때의 교훈: **안내선에 노드 색을 쓰면 관계로 읽힌다** — 회색이어야 한다).
- **같은 해의 차례는 날짜순** (`sortMarks`: 연도 → 날짜 문자열 → 가나다). 가나다면
  부산진 전투(5월)가 한산도 대첩(7월) 아래에 선다. **원인은 결과보다 위** — 한 해 안을
  위상 정렬(칸)로 세우되 세울 수 있는 것 중 날짜가 앞선 것을 고른다. 인과로 가르는 것은
  **결과의 날짜가 원인의 날짜를 품을 때만**(`dateContains`): 같은 날(한일병합 → 무단통치
  1910-08-29) · 거친 결과(을사조약 1905-11-17 → 애국계몽운동 1905) · **날짜를 모르는
  마크**(왕자의 난 → 함흥차사 — 빈 날짜는 '그 해 첫날'이 아니라 '그 해 어딘가'다) ·
  **단체의 창립이 곧 결과인 것**(3·1 운동 → 북로군정서 1919 — 연표는 단체를 시작한 날에
  세운다). 품지 않으면 날짜가 이긴다 — 원인보다 앞선 것이 분명한 날짜를 끌어내리지
  않는다(청나라의 1636년 자리는 건국 4월이다). 인과는 서버가 `causes`(같은 해 마크
  사이의 `[원인 id, 결과 id]`)로 주고 고른 노드의 `rel` 도 같은 길로 든다 — 전에는
  뒤엣것뿐이라 둘 다 뼈대인 쌍을 몰랐다 (2026-09-08, 32쌍 → 8쌍). **순환에서도 정렬이
  터지지 않는다**(진주농민봉기 ↔ 임술민란). 날짜 자체가 틀린 것은 화면이 아니라
  `chronology` 표가 고친다.
- **무엇을 어떻게 찍나**: 고른 노드 r 4 + 구간 막대 4px · 이웃·뼈대 r 2.6 · 왕조는 축
  **옆**(−6px) 2px 막대(축 위에 겹치면 사건 점을 다 덮는다) · 인물은 점이 아니다(§1.2).
  이웃의 구간은 그리지 않는다 — 축 위에서 한 덩어리가 된다.
- **이름 규칙** (`markName`): 나라는 첫 해에 `조선건국`(붙여 씀, 서버 `founded`, 일제
  강점기는 나라가 아니라 안 받는다), 인물은 **그 해가 정말 생년일 때만** `세종 탄생` —
  이름만 서면 "그 해에 무엇을 했다"로 읽힌다.
- **연도 칸** (`yearCells`, 시대·개인 연표 공용): 그 해의 첫 줄에 해, 뒤따르는 줄에 달,
  달을 모르면 해를 흐리게 되풀이, **달을 이미 적었으면 뒤 줄은 비운다**(연도는 언제나
  달보다 위 — 2026-09-08), 달은 그 줄의 해와 같은 날짜일 때만. 없는 자리를 1월 1일로
  채워 말하지 않는다.
- **원인선** (`causeWire`): `caused` 의 **들어오는 쪽만**(`isCause`) 오른쪽 여백에서
  ㄷ자(팔 12 · 안쪽 12, `#4f93bf` 1.2px)로 고른 노드와 잇고 화살촉이 고른 노드를 가리킨다.
  결과는 잇지 않고 딱지 `결과` 만 — 양쪽을 다 그리면 어느 쪽으로 읽히는지 흐려진다.
  축 위나 라벨 사이를 지나지 않는다 — 오른쪽 가장자리는 늘 비어 있다.
- **재위 띠** (`reignBand`, `REIGN_COLOR #3d84f5`, 칸 104px): 6px 알약, 이웃한 재위는
  한 칸 걸러 78%/50% (맞닿는 끝이 보이게), 고른 노드의 해를 품는 임금은 100% 에 이름이
  강조색 — "갑자사화를 고르면 연산군이 밝아진다"가 연표가 답할 물음이다. 사망은 재위의
  끝이 아니다: `DEATH_X 19` 에 속 빈 원 + 점선, 몰년 라벨은 퇴위 뒤 죽었을 때만 **이름과
  함께**(태조의 1408년이 태종 재위 한가운데 선다). 라벨 최소 간격 26px(13 이면 문종 위에
  예종이 얹혔다), 자리 없으면 막대만 남기고 칩에 `이름 12/43`. 왕은 '재위', 대통령은
  '재임', 없는 쪽은 세지 않는다. 왕조 접두는 뗀다('조선 세종' → '세종').
- **넘겨받은 연도**: 연도 노드를 타고 알아낸 것은 `연결된 연도` 알약, 이웃으로 자리만
  가늠했으면 그렇다고, 아무것도 없으면 `연도를 알 수 없습니다`. 둘을 같은 얼굴로
  내놓지 않는다.
- 걸러내는 지저분한 시간: 인물 생년=몰년, `MAX_SPAN` 인물 110 · 사건 60 넘는 구간, 피벗
  150년 밖 이웃(갑자사화 참여자에 1955년생).
- 축 아래 64px 여백(마지막 사건이 그림자에 눌린다), 위 18px. 배율·띠 여부는
  `localStorage`. 스크롤은 고른 자리로 부드럽게, 가는 도중 ResizeObserver 가 끊지 않게
  `seeking` 을 든다.

## 7. 인과 도면 (`showCausal` · `causalLayout`) — 지금은 꺼 둠

`App.jsx CAUSAL_DIAGRAM = false` (2026-09-06 사용자: "지우진 말고 기능 꺼두자"). 꺼진 동안
클릭은 주변 관계를 펴고 인과 선은 굵은 회색이다. **다시 켤 때 규칙**:

- 처음 열릴 때(부팅·검색·주소)는 주변 관계 그래프 그대로. 노드를 누르거나 상세·연표에서
  고르면 `/api/chain` 을 **두 걸음만** 받아 도면을 세운다 (네 걸음은 심하전투 원인 31개가
  한 화면에 겹쳤다). 더 앞은 도면 안의 노드를 눌러 이어 간다 — 점진 탐색. 인과가 없는
  노드는 주변 관계를 편다. 빈 곳·Esc·더블클릭은 접힌 배치로 돌아온다(`_saved`, alpha 0.12).
- **층 매기기는 수기야마의 가장 긴 경로**: 0열 고른 노드, 왼쪽 원인, 오른쪽 결과. 한
  노드는 한 번만 서고 모든 선이 왼쪽 → 오른쪽 (가까운 열에 두면 후금 → 정묘호란이 같은
  열 안에 서서 방향이 사라진다). 열 안은 연도순 → 모르면 뒤 → 가나다. 순환은 되돌아오는
  선을 뺀다.
- **화면 자로 잰다**: 열 간격 120~230px = 화면 폭 ÷ 열 수, 줄 간격 40~58px = 높이 ÷ 가장
  긴 열, 배율 1. 이름표는 11px 고정이라 줄 간격을 배율로 줄이면 겹친다. 캔버스 크기가
  바뀌면 다시 잰다.
- 선은 열 사이 3차 곡선(접선 수평, `bend = max(40, Δx/2)`) — 곧은 선은 중간 열의 점을
  가로지른다. 파랑 `CAUSE_LIT` 2px, 추출은 파선, 화살촉은 끝 접선. 종류 라벨은 선 한가운데,
  선이 24 를 넘으면 가리킨 경로에만. 노드를 가리키면 그 노드를 지나는 경로만 밝다.
- 열 머리를 글자로: 원인 · 원인의 원인 · 더 앞선 원인 / 결과 · 결과의 결과 · 더 뒤의
  결과 ('원인의 원인의 원인'은 안 읽힌다). 이름은 전부 쓰고 아랫줄에 연도.
- 안내 칩: `심하전투의 인과 · 원인 16 · 결과 11 · 노드를 누르면 …`.
- 도면은 자료 오류를 드러낸다 (심하전투 1619 의 결과로 표전문제 1395 가 섰다) — 화면이
  고치지 않고 `chronology` 관문의 몫이다.

이웃 그래프 위에 색선을 얹어 관계 종류를 "강조"하는 방식은 다시 쓰지 않는다 — "정보값이
없다"로 두 번 돌아왔다.

## 8. 개인 역사 (`life.js` · `LifeView.jsx` · `life.py`)

사용자 지시문(`life_prompt.md`)은 고치지 않는다. 검증·날짜·연결·다듬기는 코드가 한다.
개인 자료는 `data/life/`, 저장소 밖. 화면이 읽는 것은 계정 → `localStorage` 이지 서버
폴더가 아니다. **배포한다** (2026-09-09, `vite.config.js LIFE_PAGE = true`) — 배포에서는
로그인한 사람만 쓰고, 서버에 파일이 남지 않는다.

**그래프는 한국사 그래프와 같은 캔버스·같은 규칙이다.** 다른 것은 자료뿐:
- 지시문의 37 타입은 `GRAPH_TYPE` 으로 8 색에 접힌다 (heritage 는 안 쓴다): 가족·친구·
  조상 → person 파랑 / 학교·회사·단체·사업·프로젝트·투자 → org 크림 / 개인 사건·전환점·
  위기·성취·실패·결정·기억·역사 사건 → event 주황 / 장소들 → place / 책·영화·음악·만화·
  게임 → artwork / 종교·문화·기술 환경 → media / 때·인생 단계·시기 → period / 직업·취미·
  기술 → role. 이름표에는 원래 타입(가족·책)이 `kind_label` 로 남는다. 범례 묶음 이름은
  `GRAPH_TYPE_LABEL`(인물·가족 / 학교·회사·단체 / 사건·기억 …).
- 관계는 `LIFE_EDGES` — `EDGE_TYPES` 와 같은 꼴 (일반 이름, 출발 갈래, 도착 갈래). 어긋난
  것은 `RELAX` 가 옮긴다 (주인공 → 자기 사건의 `after`·`during` → `experienced`(당사자),
  사건 → 학교의 `studied_at` → `at`(곳)). **역할이 선의 이름**: 주인공 → 사건은 사건 이름
  꼬리의 술어(입학·졸업·이주·창업), 남은 '함께', `met` + '친구' 낱말 → `friend_of`. '뒤'·
  '동안'·'수학'·'겪음'은 어느 선에도 서지 않는다 (2026-09-08 "친구들은 만남이 아니라
  '친구'라고 표시해야. '뒤', '동안' 이런 설명은 도대체 뭐야?" → "한국사 그래프 만들 때 적용한
  방법을 체크해보고 다시 만들어").
- **[코드] 연표가 이미 그리는 것을 선으로 또 말하지 않는다** (2026-09-08 사용자, '성일초등학교
  입학' 상세의 `다음  성내초등학교 전학` 을 보고: "다음 이라는 메뉴는 뭐야? 별 정보값이 없는데
  그냥 삭제해"). 사건과 사건의 **차례**(`before` '다음' · `after` '이전')는 연표가 연도로 이미
  그리므로 선으로도 관계 목록으로도 세우지 않는다 — `SEQUENCE_ONLY`(`life.py` · `life.js` 같은
  표). 모델이 답하는 것은 막지 않는다(스키마 enum 에 남는다): 주인공 → 자기 사건을 `after` 로
  답하기도 하고 그것은 **참여**라 뜻이 있다. 그래서 버리는 자리는 `tidy_edges`/`tidyEdges` 의
  **RELAX 뒤** 한 곳뿐이고(옮길 데가 있으면 옮기고, 사건 → 사건으로 남은 것만 버린다), 계정·
  브라우저에 남은 옛 그래프도 새로고침으로 여기서 사라진다. `during`·`overlapped` 는 차례가
  아니라 포함·겹침이라 남는다. **일반화**: 관계가 말하는 것이 이미 다른 부호(축·색·크기)로
  서 있으면 그 관계는 선이 아니다 (§0.2 '한 뜻을 두 부호로 말하지 않는다').
- 그래프는 작아서 **통째로** 준다(수십 노드), 중심은 고른 노드 → 주인공 → 첫 노드. 차수는
  엣지에서 직접 센다. 주인공과 떨어진 섬은 `linkOrphans` 가 `experienced`(0.8)로 잇되
  남의 사건과 세계사 사건은 그대로 둔다. 범례 선은 '본인이 말한 것 (확실)' · '말한 것에서
  미룬 것'(점선) 둘 — same_as 도 인과 굵기도 없다.
- **[코드] 가족은 이야기가 호칭으로 말한 것이라 코드가 잇는다** (`link_people` · `linkPeople`,
  2026-09-08 사용자: "왜 엄마라고 분명히 말했고 엄마는 매우 중요한 사람인데 그래프에서 나와
  엄마 사이에 엣지를 그리지 않았지?"). 한 문장(또는 바로 앞 문장)이 호칭(엄마·아버지·할머니·
  형·동생·아들·아내 …)과 이름을 함께 부르면 `LIFE_EDGES` 의 가족 관계를 표의 방향대로 세우고
  **호칭이 선의 이름**이다 (parent_of 는 부모 → 자녀, 형제·배우자·친척은 `relative_of` 에 호칭).
  '김일권의 엄마'는 남의 가족. 실측 원인: 더한 토막의 답에 주인공 노드가 없어(옛 그래프에
  있다) `validate` 가 `person_mother → person_1` 을 "양끝이 없다"고 버렸다 — 주인공 id 는
  노드에 없어도 관계의 끝이다. **사람 섬은 남기지 않는다**: 호칭이 없으면 이야기가 이름을
  부를 때 `met`(0.8). 이미 이어진 사람은 건드리지 않는다(가족 관계의 빈 역할만 채운다).
  사람의 날짜는 이름 문장에 해가 없고 앞 문장이 호칭으로 부르면 앞 문장의 것도 '말한 것'이다.
- **[코드] 근거가 되는 글은 `stories` 다.** `linkPeople`·`participantsFromStory`·
  `gate_connections`·`dateSaid` 가 전부 그 글에서 근거를 찾으므로, 글이 빠지면 **관계가
  조용히 사라진다**. `data/life/*.json`(서버 저장본)은 늘 마지막 한 줄이 뒤처진다 —
  화면이 `base` 로 보내는 것이 보내기 **전**의 문서라서다. 그래서 그 파일로 재면 없는
  병이 보인다 (2026-09-08 실측: 서버 파일에서 '백경순'이 섬이었는데, 화면이 쥔 문서로
  재니 `백경순 —엄마→ 나`가 제대로 서 있었다. 엄마를 말한 글이 그 파일에만 없었다).
  **개인 그래프를 잴 때는 화면이 쥔 문서(계정 → `localStorage`)로 잰다.**
- 두 곳에서 싣는다(`useEffect` + `onReady`) — StrictMode 가 캔버스를 떼었다 붙인다.

**연표는 세 열이 자 하나 위에 선다** (`buildScale` 공용, `ZOOM 5`):
```
왕·대통령 띠 104 | 한국사 208 | 홈 28 | {이름}의 역사 214 (오른쪽 24 는 인과 선) | 단계 띠 78   = 644px, 최대 45vw
```
- 한 해의 높이는 **두 열 중 더 몰린 쪽**이 정한다 — 같은 해가 세 열에서 같은 높이여야
  "IMF 때 아버지 인쇄소가 부도났다"가 선 하나로 읽힌다. 축은 이 사람의 삶(생년−2 ~
  오늘+1). 태어나기 전의 역사는 축이 아니라 **캔버스 머리의 줄**에, **이어진 것만**
  (6·25 전투 서른 개가 머리를 채우면 이어진 한 줄이 묻힌다).
- 역사 열: `_anchors` 와 같은 규칙의 큰 사건(r 2.6 faint) + 모델이 부른 이름 중 그래프에
  없는 것은 속 빈 점 + 딱지 `그래프에 없는 사건`, 링크 없음 — 그래프인 척 세우지 않는다.
  이어진 것은 r 3.4 파란 테두리. 개인 열: 파랑 점, 반지름 `2.4 + 중요도/4`, 구간은 막대.
- **역사 → 개인 선**: 홈을 건너는 S 곡선, 직접 실선 · 간접 점선 `3 3`, 개인 열 왼쪽
  가장자리에서 화살촉. **`possible` 은 선을 긋지 않는다** — 모델의 짐작을 선으로 그으면
  읽는 사람에게 인과가 된다 (세월호 → 퍼듀 졸업). 서버 `gate_connections` 가 원문이 그
  사건을 이름으로 부르지 않았거나 역사가 개인 사건보다 뒤인 연결을 먼저 버린다. 그래프에
  이을 때는 **타입 event · 이름 정확 일치 · 해 ±1** 셋 다 맞아야 한다.
- 개인 인과(`caused`·`triggered`·`led_to`·`resulted_in`)는 시대 연표와 같은 ㄷ자 선,
  선마다 4px 안으로. 원인이 아래면 날짜가 틀린 것이라 그리되 `backwards` 표시.
- **같은 해의 차례는 연표의 차례**(입력 순 안정 정렬), 학제 사다리만 예외(초1 < 중2 < 고3
  < 대4 < 원5 × 들어감 0 · 다님 1 · 나옴 2). 해가 사다리를 어기면 해가 틀린 것 — 세어
  알리고 코드가 옮기지 않는다. 달까지 아는 날짜는 항목의 해를 이긴다(1998-04-24 공연이
  1997 칸에 '4월'로 섰다).
- 인생 단계 띠는 **맨 오른쪽**(개인 열 왼쪽에 두면 연결선이 띠 이름을 가로지른다), 강조색,
  한 칸 걸러 75%/45%, 다음 단계 앞까지 — 군복무는 전역·소집해제에서 닫는다(안 닫으면 2년이
  4년으로 칠해진다). `MILITARY` 정규식이 모델의 '사회생활'을 이긴다.
- 인물의 해는 **이야기가 말한 날짜가 있을 때만**(`dateSaid`: confidence 1) — 사람 노드의
  해는 생년이 아니라 내 삶에 들어온 해라 이름 옆 숫자는 생년으로 읽힌다. 주인공은 연표
  항목이 아니라 연표 그 자체. 생일은 '출생' 사건의 날짜가 노드의 1월 1일을 이긴다.
  나이는 `만 N세`. `person_1` 같은 식별자는 한글이 아니면 그 줄을 세우지 않는다.

## 9. 글자 — 문장·머리·빈 상태

- **관계는 한국어 문장이다.** 조사는 받침으로 가른다(`pt`: 은/는, 을/를, 이/가, 과/와).
  주어·목적어는 `dir` 로 정하고, 인과의 상대가 서술구면 그 구로 부른다('후금의 파약
  행위는 병자호란의 원인이 되었다'). 문장 규칙이 없는 타입은 화살표 폴백이 서므로 새
  타입은 문장을 같이 만든다(§1.4).
- **묶음 머리**: 역할 > 방향 이름 > 타입 이름. 근거 구절은 둘 이상이 공유하면 묶음
  머리에 한 번만(열거문 하나가 관계 여럿을 낳는다). `related_to` 는 같은 상대에 구체 카드가
  있으면 접고 근거만 옮긴다(정약전이 부모로 한 번, 관련으로 또 한 번).
- **상세 패널은 문서 한 장**: 되돌아갈 노드(sticky) → 타고 들어온 관계(강조 15% — 이
  패널에서 강조 바탕은 여기뿐) → 타입 딱지(색 견본 + 글자) → 제목 → 기간 → 본문(상자
  없음, 요약만 — 전문은 애드센스 '주의 필요') → **출처 한 줄**(유일한 예외) → 다른 이름 →
  인과 사슬 → 관계(카드 아니라 줄). 자취는 상세 안에서만 쌓인다 — 캔버스에서 고른 노드는
  그 자체가 뿌리다.
- **빈 상태는 이유를 가른다**: 설명 없음은 `whyEmpty` — 연표 눈금 / 산문에서 이름만 /
  국가유산청에 해설 없음 / 한국어로 못 옮김 / 위키백과 문서 없음 / 아직 안 받아옴.
  '자료 없음'으로 뭉뚱그리면 채워질 노드와 채울 것이 없는 노드가 같은 말을 한다.
- **영어·식별자·출처 딱지 금지.** `aria-label` 도 한국어. 시대 이름은 서버가
  `meta.era_label` 로 준다 — 화면이 영어 키 번역표를 들지 않는다(빠뜨린 하나가 그대로
  영어로 뜬다). 개인 역사의 타입·관계 이름도 `NODE_TYPE_KO`·`EDGE_TYPE_KO` 로만.
- 사슬 나무는 `←` 글자가 아니라 실선(`chain-elbow`·`chain-stem`)으로 잇고, 자식 단의
  세로선은 부모의 점에서 시작한다. 사슬 머리는 타입별('이 일을 부른 것' 은 사건에만,
  인물은 '이 인물에서 비롯된 일'). 멀리 이어진 것을 칩으로 되풀이하지 않는다 — 나무가
  이미 말한다. 경로 검색은 나무 아래 접어 둔다.

## 10. 값이 사는 곳과 검증

**색을 바꾸면 네 곳 + 테스트**: `graph-view.js TYPE_COLOR`·`TYPE_COLOR_LIGHT` →

따로 산다 — 손대지 않는다.

**머리 표는 두 벌이 같아야 한다**: `server.ROLE_HEADS/LABEL_HEADS/LABEL_DIR_HEAD` =
`relations.js` 의 같은 이름. 개인 역사는 `life.py LIFE_EDGES/RELAX/LIFE_STAGES` =
`life.js` 의 같은 이름 (테스트가 지시문을 읽어 빠진 것을 잡는다).

```bash

python3 tools/check_palette.py          # 노드 색을 만졌으면 — 2형·1형 5.0 이상
```

**화면은 CDP 로 본다** — 8100(빌드본)과 5173(개발 서버, 사용자가 보는 것) 둘 다.
`window.__histgraphView` 로 노드 자리를 읽어 누르고 찍는다. `--virtual-time-budget` 은
RAF 때문에 안 끝난다. 크롬이 옛 index.html 을 캐시하니 `Page.reload({ignoreCache:true})`.
`serve` 는 `src/` 를 다시 읽지 않는다 — 고치면 8100 을 다시 띄운다. 화면이 읽는 DB 는
`data/korea.sqlite` 파생본이다 — 원본만 고치면 화면은 그대로다.

## 12. 새 것을 그릴 때 — 정하는 원리와 더한 규칙

규칙에 없는 것이 오면 이 순서로 정한다: (1) 그것은 온톨로지의 무엇인가(타입·관계·속성·
상태) → (2) 그 뜻은 §4 의 어느 변수에 실리는가, 그 변수가 비어 있는가 → (3) 자료가 몰리면
어떻게 접히는가(잘라 내지 않는다) → (4) 모를 때 무엇이라 적는가 → (5) 무엇으로 재는가.
정한 것을 이 파일에 적는다.

이 문서가 새로 세운 규칙 (전부 **[제안]**, 코드로 옮기면 표식을 지운다):

1. ~~대칭 관계에는 화살촉이 없다~~ → **코드로 옮겼다** (2026-09-08, `graph-view.MUTUAL`).
   같은 표가 선을 한 줄로도 접는다. §2 참조.
2. **같은 쌍의 다른 타입 선은 겹치지 않는다** (§2). 오프셋 또는 라벨 합치기. (같은 쌍·
   **같은** 타입의 두 방향은 1 이 접었다. 남은 것은 '자녀'와 '사제'처럼 타입이 다른 것.)
3. **예산에 걸려 접은 것은 언제나 글자로 적는다.** 그래프의 `차수 상위만 표시`, 재위 띠의
   `이름 12/43` 처럼 — 연표·사슬·개인 역사에서도 무엇을 접었는지 수를 적는다. 접었다는
   사실 없이 적게 보이는 화면은 없어야 한다.
4. **대비 하한 셋** (§4): 1px 선 2.7:1 · 글자 4.5:1 · 물러난 노드 2.5:1. 새 색은 두 테마
   에서 다 잰다.
5. **alpha 를 만지는 코드는 §3 의 목록에 적는다.** 목록 밖에서 데우면 배치가 영영 식지
   않는 병이 돌아온다.
6. **레벨-오브-디테일은 배율 문턱으로 정한다.** 이름표(`textFade`), 관계 이름(k > 0.5,
   이웃 ≤ 16), 도면 라벨(k > 0.35, 선 ≤ 24) 처럼 새 장식도 배율과 개수 문턱을 둔다 — 늘
   그리는 장식은 허브에서 겹친다.
7. **한 캔버스에 크기 부호는 하나.** 역사·개인 그래프의 노드 크기는 차수뿐이다. 연표의
   개인 점만 중요도다 — 같은 화면에서 크기가 두 뜻을 갖지 않게 한다.
8. **상태는 링과 글자로, 색상으로 하지 않는다.** '고름·중심·가리킴' 외의 새 상태(예:
   '검토 필요')가 필요하면 링 모양(점선 링)이나 딱지로 — 노드 색을 바꾸면 타입이 바뀐 것
   으로 읽힌다.
9. **화면은 서버가 준 것만 그린다.** 화면 코드가 노드를 지어내거나(모델이 부른 이름), 관계를
   추정하거나, 날짜를 채우지 않는다. 그래프에 없는 것은 없다고 표시한다(`그래프에 없는
   사건`, 속 빈 점).
10. **새 화면의 시간 방향은 위 = 과거, 왼쪽 = 원인.** (§2) 한 축 위에서 차례가 곧
    시간으로 읽히면 **원인이 결과보다 앞에 서야 한다** — 날짜가 그 차례를 못 말할 때
    (같은 날 · 거친 날짜 · 빈 날짜 · 단체의 창립)는 인과가 차례를 정하고, 날짜가 분명히
    다르면 날짜가 이긴다. 그렇게 세우는 자리는 위상 정렬로 짜되 **순환에서도 결과를
    낸다** — 자료에는 서로를 원인으로 무는 쌍이 실제로 있다.
11. **모르는 값은 극단이 아니라 '어딘가'다.** 빈 날짜를 '그 해 첫날'로, 연도만 아는
    날짜를 '1월 1일'로 읽으면 화면이 모르는 것을 아는 척한 것이 된다 (함흥차사가 제
    원인 위에 섰다, 2026-09-08). 다른 부호에 기대어(인과·관계) 자리를 좁힐 수 있으면
    좁히고, 없으면 물러난 자리에 둔다.
12. **터치·키보드**: 히트 영역은 반지름 + 6 이상, `touch-action: none` 은 캔버스에만,
    연표는 그냥 휠이 스크롤이어야 한다(줌은 ⌘/Ctrl + 휠·핀치). 새 제스처는 이 표에 적는다.
13. **한 노드가 두 자리에 서지 않는다.** same_as 로 이어진 둘은 34px 로 붙이고, 연표에서
    이름도 해도 같으면 한 줄, 상세에서 대칭 관계는 카드 한 장, 사슬에서 한 노드는 가장 긴
    경로의 열 한 곳. 새 화면에서도 같은 실체가 두 번 보이면 그것부터 고친다.
